# AI Verification Notes

> The brief requires at least one documented case where AI output was wrong or risky, and how it was caught. AI (Claude Code) was used for codebase surveys, drafting, and implementation; every claim below was checked against code, logs, or a live run before it was relied on. Entries are added as they happen.

| # | Date | What the AI said or did | How it was checked | Outcome |
|---|---|---|---|---|
| 1 | 2026-10-20 | The first `CLAUDE.md` framed the work as a **"quality-engineer case study"** with a "log before fixing" rule, taken from the root README. | Read the actual brief (`brief-fullstack.pdf`): it is a **Fullstack Product Engineer** brief that expects shipped improvements, not only an audit. | **Wrong.** Framing and workflow rule corrected before any work started. Lesson: the README is not the brief. |
| 2 | 2026-10-20 | Told the user to run `bin/rails secret`. | User ran it: `permission denied`. `git ls-files -s api/bin/` showed mode `100644`. | **Wrong**: an unverified instruction. Switched to `bundle exec rails`; logged as F-026. |
| 3 | 2026-10-20 | A codebase survey claimed Gemini HTTP **retries never fire** despite `max: 3` being configured. | Checked faraday-retry 2.4.0's default methods (`[:delete, :get, :head, :options, :put]`, no POST), and counted session-2 logs: **13 × HTTP 503, 0 retry log lines**. | **Correct**, now backed by evidence (F-008). It would not have been reported on the survey's word alone. |
| 4 | 2026-10-20 | The interview instructions predicted the session would "end by itself at ~10 minutes" if the candidate didn't press End. | Session 2 ended at **8 min 24 s** with `reason=all_covered` while all skills were `not_yet`; the log shows the closing-phrase fallback fired. | **Wrong prediction**, and the miss exposed a real defect (F-006). The prediction came from the prompt's rules, not from the runtime fallback that overrides them. |
| 5 | 2026-10-20 | The sample config's Gemini model names were assumed usable. | Listed the models available to the key, then called each candidate model on the `v1` endpoint the client actually uses: `2.0-*` gone, `2.5-*` closed to new keys, Pro models `v1beta`-only. | **Risky assumption** caught before it surfaced as an app bug (F-024). |
| 6 | 2026-10-20 | AI-written migration `AllowNotAssessedSkillRatings`: `up`, `down` and `up` again all passed on the dev database. | Re-ran the rollback **with a not-assessed row present** (the case the migration exists for). `down` failed: `PG::CheckViolation … chk_portfolio_skills_rating_complete`, because it backfilled `ai_level` while the new both-or-neither constraint was still active. | **Wrong.** The happy-path rollback passed only because no NULL rows existed. Fixed by dropping the constraint before the backfill, then re-verified: NULL → `1 / low / ''` on rollback, and migrating forward again works. |
| 7 | 2026-10-20 | AI-built report UI: 44 component and page tests passed, and the typecheck and lint were clean. | Opened the real pages with the demo seed in a browser at 1280 px and 390 px, and took screenshots. | **Three layout defects the tests couldn't see:** level badges sized by their description, so skill titles didn't line up; the shared header overflowed to 550 px on a 390 px phone; and on mobile a long skill name ran under the "Rate manually" button. Fixed (fixed badge width, collapsing header, action on its own row) and re-checked: `scrollWidth` 390, no overlaps. |
| 8 | 2026-10-20 | Recaptured the "before" screenshot to remove a real name, *after* session 1's report had been regenerated by the new engine. | Reviewing the exported report: the "before" image showed three comparison rows and no culture paragraph, contradicting its own caption (one row, culture paragraph shown, verdict hidden). The old UI had rendered *new* data. | **Wrong: a misleading before/after.** Restored session 1's report row from the API response recorded before any regeneration, recaptured the old UI, and checked the page text (verdict hidden, culture shown, one row) before regenerating for the "after". |
