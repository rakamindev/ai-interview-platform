## Tabel Ringkasan Asumsi

| :--- | :--- | :--- | :--- |
| **ASUMSI-01** | Lingkungan | Port web disetel ke `:5173` (Vite) dan backend Rails ke `:3001`. Link undangan diarahkan ke tampilan web kandidat. | Panduan utama `README.md` menyebut port 3001 untuk API dan 5173 untuk web. Nilai bawaan sistem yang mengarahkan link undangan ke port 3001 adalah kekeliruan konfigurasi, sehingga harus diarahkan ke antarmuka web kandidat (`http://localhost:5173`). |
| **ASUMSI-02** | Lingkungan | Menggunakan model AI aktif generasi baru (`gemini-3.8-flash` / `gemini-3.5-flash`). | Model bawaan di panduan awal (`gemini-2.0-*`) sudah ditutup oleh Google (Error 404), sedangkan model Pro memiliki batasan kuota 0 pada akun gratis (Error 429). Model Flash baru terbukti stabil, cepat, dan akurat dalam menilai kandidat. |
| **ASUMSI-03** | Lingkungan | Versi Ruby 3.3.2 dan Bundler 2.5.11 dipertahankan tanpa perubahan dependensi besar. | Mencegah kerusakan dependensi (*dependency drift*) dan memastikan aplikasi berjalan 100% cocok dengan berkas `Gemfile.lock` bawaan tim Rakamin. |
| **ASUMSI-04** | Keamanan | Pemisahan data antar perusahaan (*multi-tenant*) bersifat mutlak dan tidak boleh bocor. | Setiap asesor atau manajer perekrutan hanya berhak melihat, mengubah, dan mengunduh data kandidat milik perusahaannya sendiri. Sistem tidak boleh percaya begitu saja pada angka ID di URL tanpa memeriksa pemilik sahnya. |
| **ASUMSI-05** | Integritas Data | Koreksi dan catatan asesor manusia adalah acuan kebenaran tertinggi (*source of truth*). | Hasil analisis AI bisa dihitung ulang kapan saja dari transkrip percakapan, sedangkan catatan dan nilai dari asesor manusia tidak bisa digantikan. Oleh karena itu, sistem wajib mempertahankan nilai manual asesor saat data diproses ulang (*upsert/merge*), bukan menghapusnya dengan `destroy_all`. |
| **ASUMSI-06** | Regulasi & Hukum | Persetujuan rekaman suara wajib dipenuhi sebelum wawancara dimulai (Kepatuhan UU PDP No. 27/2022). | Berdasarkan hukum perlindungan data pribadi di Indonesia, rekaman suara tergolong data biometrik spesifik. Wawancara dan rekaman tidak boleh dimulai sebelum kandidat secara sadar mencentang lembar persetujuan pemrosesan data oleh AI. |
| **ASUMSI-07** | Pengguna & Produk | Pembuatan akun asesor dikelola terpusat oleh admin perusahaan (bukan pendaftaran bebas). | Platform wawancara B2B antar perusahaan mengandalkan pemberian akses terpusat oleh admin organisasi atau sistem akun induk Rakamin. Form pendaftaran mandiri yang terbengkalai dibersihkan dari kode (*dead code*), dan pengguna diarahkan menghubungi admin perusahaannya. |
| **ASUMSI-08** | Rekomendasi Produk | Integrasi login Google Workspace khusus domain kantor untuk sistem induk Rakamin. | Untuk pengembangan ke depan, sistem disarankan menggunakan *Single Sign-On* (SSO) Google Workspace pada gerbang login utama Rakamin dengan menolak email publik gratisan (seperti `@gmail.com` atau `@yahoo.com`) demi memastikan hanya akun perusahaan mitra yang bisa masuk. |
| **ASUMSI-09** | Kontrak Tampilan | Laporan kecocokan lowongan (*Fit/Gap*) harus mengirimkan target nilai yang diminta dan status koreksi asesor. | Antarmuka web membutuhkan target nilai lowongan (`required_level`) dan tanda pensil koreksi manual (`✏️`) agar asesor dapat melihat perbandingan skill kandidat secara transparan. |
| **ASUMSI-10** | Jaringan | Uji kelayakan internet harus mengutamakan koneksi langsung ke server aplikasi sendiri. | Menghubungi server aplikasi kita sendiri jauh lebih akurat untuk memastikan kelancaran suara wawancara daripada bergantung pada server luar, serta mencegah kandidat gagal tes hanya karena server luar diblokir oleh jaringan kantor. |
| **ASUMSI-11** | Sistem Desain | Antarmuka alat kerja B2B lebih optimal dengan estetika flat dan keselarasan tata letak (UI Polish). | Asesor membutuhkan antarmuka yang bersih, flat tanpa bayangan bertingkat yang tidak perlu, dan presisi sejajar agar fokus membaca data evaluasi, bukan elemen dekoratif yang saling bertabrakan. |
| **ASUMSI-12** | Tata Letak (Layout) | Tata letak asesor berbasis collapsible sidebar modern dengan navigasi hierarkis, tabel independen bebas pergeseran, dan adaptasi mobile utuh. | Pengalaman kerja asesor di layar lebar membutuhkan ruang kerja vertikal maksimal yang didukung sidebar dapat-ciut (*collapsible* 56px/256px), breadcrumbs dinamis untuk melacak kedalaman halaman, tabel dengan persentase lebar terkunci agar aksi salin tautan tidak menggeser kolom lain, serta adaptasi otomatis ke kartu dan drawer saat diakses dari perangkat bergerak (*mobile responsive*). |
