Hasil Eksekutif Utama yang Dihasilkan:
  • Jaminan Nol Kehilangan Data (P0-1): Override kalibrasi asesor dipertahankan 100% saat regenerasi portofolio AI via snapshot value-object dalam transaksi atomik.
  • Perutean Kandidat Tuntas (P0-2): Menuntaskan galat 404 pada URL undangan dengan menyelaraskan host ke port frontend (5173).
  • Hardening Klien AI (P0-3): Klien Gemini diperkuat via negosiasi MIME JSON (application/json) dan sanitasi regex code fence.
  • Kepatuhan UU PDP (P0-4 & P1-2): Filter parameter Rails memblokir PII pada log; modal persetujuan React membatasi akses mikrofon sebelum izin.
  • Keandalan Hardware & Operasional (P1-5, P1-6, P2-4): Pelepasan track mikrofon deterministik menghindari NotReadableError, mitigasi penutupan WebSocket 1008/1006 dengan state machine fallback, serta Screen Wake Lock API dengan pemulihan otomatis saat tab fokus kembali.

1 Konteks Produk & Imersi Domain

1.1 Lanskap Rekrutmen Teknologi Indonesia & Pilar Produk

Di Indonesia, perusahaan teknologi bervolume tinggi dan platform perbankan digital memproses 500–1.500 kandidat per lowongan terbuka. Tim rekrutmen menghabiskan hingga 70% kapasitas awal membaca CV bertemplat dan melakukan phone screen repetitif. Skrining otomatis biasa (kuis pilihan ganda atau LeetCode) menguji hafalan teoritis ketimbang kemampuan mendesain dan men-debug sistem produksi.

AI Interview Platform memberikan nilai ungkit nyata melalui wawancara percakapan dinamis yang menggali depth of reasoning dengan rubrik terstandarisasi (L1–L5):

  • Evidence Grounding (Berbasis Bukti Nyata): Setiap skor AI wajib mengutip transkrip verbatim kandidat secara langsung guna mencegah halusinasi AI.
  • Human-in-the-Loop Authority (Otoritas Asesor Manusia): Asesor memegang otoritas kalibrasi final; penilaian AI merupakan baseline yang dapat di-override dengan catatan audit.
  • Multi-Persona Utility (Utilitas Multi-Persona): Perekrut mendapatkan pipeline terorganisir; asesor memperoleh kartu bukti granular dan matriks fit/gap lowongan.

1.2 Mandat Hukum & Etika: Kepatuhan UU PDP No. 27/2022

Kandidat menjalani evaluasi sebagai prasyarat kerja. Undang-Undang No. 27 Tahun 2022 tentang Pelindungan Data Pribadi (UU PDP) menetapkan kewajiban hukum ketat bagi platform evaluasi:

  • Pasal 20 & 21 (Persetujuan Eksplisit): Pemrosesan audio/biometrik dan profiling otomatis wajib mengantongi izin eksplisit kandidat sebelum sesi dimulai.
  • Pasal 35 & 39 (Kerahasiaan & Anti-Bocor): PII (nama kandidat, audio chunk, transkrip) wajib dicegah dari kebocoran ke log aplikasi dan telemetri.
  • Pasal 8 (Transparansi Rubrik & Hak Penjelasan): Kandidat berhak memahami kriteria evaluasi; skor tidak boleh menjadi kotak hitam (black-box) sepihak.

3 Strategi Arsitektur & Analisis Trade-off

Kami mengevaluasi dua arsitektur fundamental untuk mesin eksekusi wawancara percakapan:

Opsi A: Aliran Audio LLM Langsung Ditolak

WebRTC / Bidirectional WebSocket langsung ke Gemini Live API

  • Latensi Giliran: Sub-detik (~400–600ms) speech-to-speech.
  • Jaringan 4G Indonesia: Sangat Rentan. Packet loss memutus soket; seluruh wawancara terhenti tiba-tiba.
  • OpEx: Tinggi (~$0.06/menit) untuk streaming token multimodal berkelanjutan (~$2.70/sesi).
  • Audit UU PDP: Liabilitas tinggi; aliran audio melewati rekaman audit persisten lokal.
Opsi B: Pipeline Event Asinkron Terpisah Dipilih

Browser WSS → Rails API & Redis → Sidekiq Workers → Gemini Engine

  • Latensi Giliran: Moderat (~800–1200ms) per giliran percakapan.
  • Jaringan 4G Indonesia: Sangat Tangguh. Potongan audio finit; rekoneksi otomatis menjaga state.
  • OpEx: Optimal (~$0.005/menit) inferensi token teks dengan prompt caching (~$0.25/sesi).
  • Audit UU PDP: 100% patuh; setiap giliran tersimpan di PostgreSQL beserta stempel waktu presisi.
Dimensi Evaluasi Opsi A: Aliran Audio Langsung Opsi B: Pipeline Asinkron Terpisah (Dipilih)
Ketahanan Jaringan (4G Indonesia/Asia Tenggara) Sangat Rentan: Jitter/packet loss memutus soket; sesi wawancara terhenti sebelum selesai. Sangat Tangguh: Buffer per potongan (chunk) & percobaan ulang otomatis menjaga integritas transkrip.
Biaya Operasional (OpEx per sesi) Tinggi (~$2.70 per 45 menit wawancara). Optimal (~$0.25 per 45 menit wawancara) melalui prompt caching teks.
Jejak Audit Hukum UU PDP Tidak dapat diverifikasi tanpa perekaman sisi server berkelanjutan berbiaya tinggi. Persistensi Asli: Catatan audit milidetik di PostgreSQL ai_interview.transcript_turns.
Kalibrasi Asesor Manusia Terhambat; risiko desinkronisasi saat override post-hoc. Integritas Relasional Penuh: AssessorOverride tertaut langsung ke skill kanonikal.
Putusan Arsitektural Senior Staff: Opsi B mutlak lebih unggul untuk skala produksi enterprise Indonesia. Ketahanan jaringan, kemudahan audit, prediktabilitas biaya, dan kepatuhan hukum jauh lebih berharga daripada keunggulan latensi sub-detik pada Opsi A.

4.1 Sorotan Kode Kritis

1. Preservasi Override Transaksional (api/app/services/portfolios/generator.rb)
def save_skills(portfolio, data)
  ActiveRecord::Base.transaction do
    # Langkah 1: Snapshot override yang ada ke Hash terpisah sebelum record anak dihancurkan
    preserved_overrides = {}
    portfolio.portfolio_skills.includes(:assessor_override).each do |ps|
      if ps.assessor_override.present?
        key = ps.skill_id.presence || ps.skill_label.to_s.downcase.strip
        preserved_overrides[key] = {
          override_level: ps.assessor_override.override_level,
          assessor_notes: ps.assessor_override.assessor_notes,
          overridden_by:  ps.assessor_override.overridden_by,
          overridden_at:  ps.assessor_override.overridden_at
        }
      end
    end

    # Langkah 2: Pembersihan record skill lama (clean slate)
    portfolio.portfolio_skills.destroy_all

    # Langkah 3: Buat skill baru dan pulihkan kembali override asesor manusia
    (data['configured_skills'] || []).each do |skill_data|
      ps = portfolio.portfolio_skills.create!(...)
      reapply_override_if_present(ps, preserved_overrides)
    end
  end
end

3. Siklus Hidup Screen Wake Lock dengan Pemulihan Otomatis (web/src/hooks/useWakeLock.ts)
useEffect(() => {
  if (!active || !isSupported) return;
  requestWakeLock();
  const handleVisibilityChange = () => {
    if (document.visibilityState === 'visible' && active) requestWakeLock();
  };
  document.addEventListener('visibilitychange', handleVisibilityChange);
  return () => {
    document.removeEventListener('visibilitychange', handleVisibilityChange);
    releaseWakeLock();
  };
}, [active, isSupported, requestWakeLock, releaseWakeLock]);

5 AI Verification Moments (Pengawasan Kritis Senior Staff)

Kasus 1: Perangkap Cascading Deletion ActiveRecord:

Asisten AI mengusulkan untuk menyimpan override dalam array in-memory, memanggil portfolio.portfolio_skills.destroy_all, lalu memanggil override.update!(portfolio_skill: new_skill).

  1. Perangkap Relasional Berjenjang: Pada PortfolioSkill, has_one :assessor_override, dependent: :destroy menyebabkan PostgreSQL mengeksekusi DELETE SQL langsung pada record anak. Array in-memory menyimpan record yang telah hancur dan dibekukan; update! berikutnya gagal.
  2. Resolusi Staff Engineer: Mengekstrak atribut ke dalam value-object Hash Ruby terpisah di dalam transaksi atomik (ActiveRecord::Base.transaction), merekonstruksi record dengan timestamp dan catatan yang utuh.
Kasus 2: Perangkap Visibilitas Tab Screen Wake Lock:

Asisten AI menyarankan pemanggilan navigator.wakeLock.request('screen') satu kali saat mount. Standar W3C menetapkan browser otomatis melepaskan lock saat tab kehilangan visibilitas (document.visibilityState === 'hidden'). Jika kandidat berganti tab dan kembali, lock mati permanen. Senior staff merekayasa event listener visibilitychange di useWakeLock.ts yang otomatis me-reacquire lock saat tab kembali aktif.
